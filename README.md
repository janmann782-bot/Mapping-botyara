# Frame ZIP Bot

Telegram-бот: получает ZIP с пронумерованными картинками, сортирует кадры по номеру и собирает MP4 через FFmpeg.

## Что умеет

- PNG / JPG / JPEG / WebP / BMP
- естественная сортировка: `1.png`, `2.png`, `10.png`
- до 10 000 кадров по умолчанию
- размер видео строго берется с первого кадра
- проверка, что все кадры одного размера
- длительность 1 кадра кнопками или вручную
- понимает `0.04`, `250ms`, `1/25`, `25fps`
- H.264 MP4 без масштабирования
- прогресс рендера
- `/cancel` останавливает FFmpeg
- повторный рендер на другой скорости без повторной загрузки ZIP
- автоматическая очистка сохраненных кадров
- защита от ZIP с паролем, слишком большого распакованного объема и лишнего числа кадров

## Вариант 1 - быстрый запуск для маленьких ZIP

Нужны Python 3.11+ и FFmpeg.

1. Скопируй `.env.example` в `.env`
2. Вставь `BOT_TOKEN`
3. Установи зависимости:

```bash
pip install -r requirements.txt
```

4. Запусти:

```bash
python bot.py
```

Важно: официальный Telegram Bot API позволяет боту скачать только файл до 20 МБ и отправить файл до 50 МБ. Для реальных архивов с тысячами 3K кадров этот режим почти бесполезен.

## Вариант 2 - нормальный режим для больших архивов

В комплекте есть `docker-compose.yml`. Он запускает бота вместе с Local Bot API.

Local Bot API дает:
- скачивание файлов без лимита Bot API
- отправку файлов до 2 000 МБ

### Что нужно

- Docker + Docker Compose
- `BOT_TOKEN` от BotFather
- `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` с `my.telegram.org` -> `API development tools`

Скопируй:

```bash
cp .env.example .env
```

Заполни в `.env`:

```env
BOT_TOKEN=123456:ABC...
TELEGRAM_API_ID=12345678
TELEGRAM_API_HASH=abcdef123456...
```

Запуск:

```bash
docker compose up --build -d
```

Логи:

```bash
docker compose logs -f bot
```

Остановка:

```bash
docker compose down
```

Полная остановка с удалением временных кадров и данных Local Bot API:

```bash
docker compose down -v
```

## Использование

1. `/start`
2. Отправь ZIP
3. Бот проверит кадры
4. Выбери длительность 1 кадра
5. Получи MP4
6. Нажми "Сделать еще с другой скоростью", если нужен второй вариант

Команды:

- `/cancel` - остановить текущий рендер
- `/delete` - удалить сохраненные кадры

## Для 3 000 кадров по 3K

Рекомендованный режим:

```env
MAX_FRAMES=10000
MAX_UNPACKED_GB=100
MAX_CONCURRENT_RENDERS=1
CRF=18
PRESET=medium
```

При 3 000 кадрах:
- `0.04 сек/кадр` -> 25 FPS -> 2:00
- `0.05 сек/кадр` -> 20 FPS -> 2:30
- `0.10 сек/кадр` -> 10 FPS -> 5:00

FFmpeg читает кадры последовательно. Все 3 000 картинок одновременно в RAM не грузятся.

## Где меняется качество

`.env`:

```env
CRF=18
PRESET=medium
```

Обычно:
- CRF 16 - очень высокое качество, жирнее файл
- CRF 18 - хороший дефолт
- CRF 20-23 - меньше файл

`PRESET=slow` кодирует дольше, но обычно дает меньший файл при том же CRF. `medium` - нормальный баланс.

## Важное про размер видео

Бот не масштабирует изображение.

Если первый кадр `3072x1728`, итоговый MP4 будет `3072x1728`.

Если какой-то кадр другого размера, бот остановится до рендера и покажет номер проблемного кадра.


## Bothost / обычный Python-хостинг

Эта версия не требует системной установки FFmpeg.

В `requirements.txt` есть `imageio-ffmpeg`, который скачивает готовый FFmpeg-бинарник как Python-зависимость. Бот сначала ищет системный `ffmpeg`, а если его нет - автоматически использует встроенный.

На Bothost достаточно:

```bash
pip install -r requirements.txt
python bot.py
```

В переменных окружения нужен минимум:

```env
BOT_TOKEN=твой_токен
```

`FFMPEG_BIN` оставляй пустым.

Если панель сама ставит зависимости из `requirements.txt`, просто загрузи файлы и перезапусти сборку/бота.
